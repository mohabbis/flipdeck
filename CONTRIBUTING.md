# Contributing to moswagger

## Philosophy

Keep the product:

- readable
- minimal
- fast
- useful for developers and non-engineers

Avoid adding complexity that does not improve the documentation or API workflow experience.

## Recommended standards

- Use consistent endpoint naming.
- Keep UI spacing clean and restrained.
- Prefer clear wording over clever wording.
- Design for dark mode first.
- Validate OpenAPI examples before merging.

## Pull request expectations

Every PR should include:

- clear summary
- screenshots or preview links if UI changes exist
- testing notes
- updated docs if behavior changes

## Suggested future labels

- feature
- bug
- docs
- ui
- api
- ai
- enhancement
